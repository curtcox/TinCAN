TinCAN

A CAN-inspired multi-master bus that runs over sound.

Two devices in the same room, with nothing but a speaker and a microphone each, form a bus. When they transmit at the same instant, the higher-priority message survives intact — resolved bit by bit by the air itself, with no collision, no backoff, and nothing retransmitted. That mechanism is CAN's one genuinely original idea, and TinCAN is an attempt to find out whether it survives a channel whose propagation delay is measured in milliseconds.

It does, at 10–100 bit/s, within a couple of metres. That is a bad bit rate and a fine control bus.

How it works, in one page

A CAN bus is a wired-AND: a node driving dominant overrides every node driving recessive. Every transmitter reads the bus back while it drives it, so a node that sends recessive and reads dominant knows immediately that somebody with a lower identifier is talking, and withdraws. It has sent nothing that disturbed the winner, so the winner's frame is undamaged and the loser simply tries again later. Priority is resolved in the medium, per bit, for free.

TinCAN builds that same wired-AND out of two sine waves:

Bus levelTone transmittedDecided by
dominant (logical 0)f_D — 4250 Hz in the default band the fraction of in-band energy sitting at f_D, measured over a window ending at the sample point
recessive (logical 1)f_R — 3000 Hz
idlesilenceno carrier in either bin

Recessive is a tone, not silence. That single choice does most of the work: it turns the dominant decision into a ratio between two simultaneous measurements from the same microphone, so it needs no calibration and no automatic gain control; it gives a decaying echo something to compete against; it keeps voice codecs and noise gates from squelching the channel; and it makes "idle" physically distinct from "recessive", so carrier sense is a measurement rather than a bit count. The rationale explains why.

Everything above the tones is CAN with two audio-driven changes. Frames get an eight-bit alternating SYNC preamble, which is fixed-form and therefore identical for every contender — that is what lets a node measure how late it started and correct its own transmit clock before any information-bearing bit is at stake. And the acknowledgement slot is two bits rather than one, because an acknowledging node's clock is offset from the transmitter's by a full propagation delay.

Those are honest numbers, and they are the whole trade. If you want to move bytes over sound, use a packet modem — Wavest and the ggwave codec underneath it are far better at that and always will be. What they cannot give you is a shared medium where the collision of two transmissions has a defined, useful outcome. On a ggwave link, two simultaneous transmissions are two lost packets. On a TinCAN bus, they are one delivered frame and one deferred frame.

Use it

The reference implementation is dependency-free ES modules. Nothing but modem.js touches the DOM or Web Audio, so the protocol runs unchanged in Node, in a worker, and inside an AudioWorkletGlobalScope — which is where the live apps run it, because a transmit decision is due every bit boundary and the main thread cannot be trusted with that deadline. 

import { Modem } from './src/tincan/modem.js';

const modem = new Modem({ band: 'A', profile: 'T25' });
modem.on('frame', (e) => console.log('received', e.detail.frame));
await modem.start();                       // asks for the microphone
modem.send({ id: 0x123, data: [0xde, 0xad] });

And offline, with no audio hardware at all:

import { AcousticChannel } from './src/tincan/bus.js';

const ch = new AcousticChannel({
  nodes: [{ name: 'a', x: 0, y: 0 }, { name: 'b', x: 1, y: 0 }],
});
const [a, b] = ch.protocols;
b.on('frame', ({ frame }) => console.log(frame));
a.send({ id: 0x123, data: [1, 2, 3] });
ch.run(6);                                  // six seconds of simulated air

Caveats worth reading before you build on it

  • It is not CAN. No interoperability with any CAN, CAN FD or CAN XL implementation is attempted or possible. Field widths, polynomials and timing all differ.
  • There is no security. Every frame is audible to the whole room, any node may claim any identifier, and a continuous tone denies the bus to everyone. See §10.
  • Echo cancellation breaks it. A node must hear its own transmission to arbitrate at all, and AEC exists to remove exactly that. The apps ask the browser to disable it and warn you loudly when the browser declines.
  • Distance ratios matter more than distance. The binding constraint is not how far apart nodes are but how unequal the distances are — see §4.6.
  • Band A is audible, and after a while, irritating. That is the default on purpose, because it works on every device and because a bus you can hear is a bus you can debug.
